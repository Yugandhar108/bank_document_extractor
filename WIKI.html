Bank Statement Document Extractor

A small team of AI workers reads a bank statement, checks the maths, and explains mistakes in a way people can review.

Overview How To Use Architecture Tech Stack FAQs Troubleshooting Security Files

What is this project?

This project takes a bank statement PDF, such as a document with many pages and a busy transaction table, and turns it into organized data.

It does not simply ask one AI question and trust the answer. Different workers handle different jobs, normal Python rules check the numbers, and a reflection worker explains what may have gone wrong.

For a non-technical reader

Think of it as a careful office team:

  1. One person reads account details.
  2. One reads customer details.
  3. One reads the transaction table.
  4. A supervisor combines and checks their work.

How To Use

The application can be started from the project folder with Streamlit.

Current development use

  1. Open a terminal in the project folder.
  2. Install the packages from requirements.txt.
  3. Copy .env.example to .venv/.env.
  4. Add one private provider key to .venv/.env.
  5. Put permitted PDFs in data/input.
  6. Run the automated tests.
python -m pip install -r requirements.txt
python -m pytest -q

What the user will do

  1. Open the application.
  2. Select a PDF.
  3. Watch the workers process it.
  4. Review any warnings or conflicts.
  5. Approve or reject the result.

The result screen shows the extracted data, checks, conflicts, and reflection details. Document text is sent to the selected AI provider.

How It Works

PDF→Safe reader→3 workers in parallel→Merge→Checks→Reflection if needed

Implemented now

  • Every PDF page is read.
  • Paths outside the allowed input folder are blocked.
  • Three agents run concurrently.
  • Start and end timestamps prove overlap.
  • Conflicting values are reported rather than hidden.
  • Transactions are preserved without asking an AI to copy them again.
  • Dates, fields, amounts, and balances are checked.
  • Reflection runs only after validation failure.

Important design choice

The transaction list can be large. The merge stage keeps the original transaction result instead of asking another AI to rewrite the full list. This reduces cost, avoids token-limit problems, and prevents a second transcription error.

Tech Stack

Language

Python for the application logic, validation rules, file handling, and tests.

AI connection

OpenAI-compatible SDK for sending prompts to a configured model. The provider can be changed through settings.

Document reading

pypdf for extracting text from PDF pages.

Data models

Pydantic for checking that agent responses have the expected structure.

Concurrency

asyncio and worker threads for running independent AI calls at the same time.

Testing

pytest with mocked AI responses, so most tests do not spend money or require a live API.

FAQs

Does this project change the original PDF?

No. It reads the PDF and creates structured results. The original input remains unchanged.

Can it read a scanned PDF?

It can open one, but a scanned PDF with no text layer currently produces no extracted text. The application shows a clear message when this happens.

Why use multiple AI workers?

Each worker has a smaller, clearer job. This makes results easier to test and makes it easier to find which part needs improvement.

Is the result automatically trusted?

No. The validation stage checks objective rules and displays any warnings before the result is reviewed.

Is an API key required to run tests?

No. The tests use fake model responses. A real key is needed only for live AI calls.

Where are prompts stored?

Prompt files are in the prompts folder. Each prompt includes a version and a reason for the change.

Troubleshooting

No provider is configured

Copy .env.example to .venv/.env and add one valid private provider key. The application checks all supported provider settings. Do not add a key to source files.

“PDF path must be inside…”

Move the PDF into data/input. This protection prevents the application from reading unrelated files on the computer.

“Could not read PDF”

The file may be corrupted, incomplete, or not a real PDF. Try opening it in a normal PDF viewer first.

Validation says the balance is wrong

Check the original statement and the extracted debit, credit, and running balance values. The error includes the expected and actual values.

Tests cannot find a package

Run python -m pip install -r requirements.txt using the same Python environment that runs pytest.

AI response is not valid JSON

The parser handles explanations and code fences, but a completely malformed or cut-off response still needs to be retried or reviewed.

Security And Privacy

  • Provider keys are read from .venv/.env and are not displayed.
  • The environment file is excluded from source control.
  • PDF paths are restricted to the permitted input directory.
  • Uploads are limited to 25 MB, stored temporarily, and removed after processing.
  • Custom provider endpoints must use HTTPS and cannot contain login details.
  • Document text is sent to the selected AI provider, so only approved documents should be uploaded.
  • Any key previously shared publicly must be revoked and replaced.
